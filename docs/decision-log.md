# Decision log

All decisions were made 2026-10-17 during ideation. Newest decisions on a topic
supersede older ones.

| # | Topic | Decision | Notes / alternatives |
|---|---|---|---|
| 1 | Product | Lean, offline take on Highland Pro for **creative writers only** | Strip feature bloat to a laser-sharp product |
| 2 | Name | **River Writer** | |
| 3 | Positioning | **Lead with craft**; privacy/offline as proof | Alternative: lead with privacy |
| 4 | Formats | Screenplay (+ multi-cam), Stage Play, Novel/Manuscript | **Comics/graphic novels cut**; non-creative templates cut |
| 5 | Stack | **Tauri** (Rust core + webview UI) | |
| 6 | Story files | Pure `.fountain` and `.md` | Rejected: custom `.river` content file, ZIP bundles |
| 7 | Extras | Scratchpad, todos, bin kept **as plain-text dumps only** | Stored as files in the project's `_river/` folder |
| 8 | Extras location | Visible `_river/` folder in the project; sidecar created only when first used | Alternative: hidden `.river/` |
| 9 | Editor | "VS Code for writers"; no extensions | Superseded by #17 |
| 10 | History | Automatic local history on by default | User agreed |
| 11 | Extras vs branches | Shared across branches by default, per-branch optional | User agreed |
| 12 | Versioning engine | **Real git** | Considered: a simple copy-based model ("versions/alternates/take"). User clarified their concern was vocabulary, not machinery. |
| 13 | Remote | **Projects can push to git** | Briefly considered dropping push for "zero network"; user kept push. Network only on push/pull/fetch/clone. |
| 14 | Vocabulary | **Standard git terms** (commit, branch, merge, diff, tag, push, pull…) | Considered: bilingual labels, writer-renamed terms (Version/Alternate/Take/"The River"), river-themed and desk-and-paper metaphors. User chose git terms: "simpler, it will be a learning curve." |
| 15 | Git UX | No staging area; stash/rebase/reset/detached HEAD hidden; autosave never pushed; scene-level diff/merge | Learning softened with hints, tooltips, "Git for Writers" guide |
| 16 | Revision marks | Derived from the diff since a tag | Replaces Highland's confusing in-document revision objects |
| 17 | UI | **Exactly like VS Code**: activity bar, side bar (Explorer/Search/Source Control/Outline/Characters), editor groups and tabs, preview to the side, diff editor, minimap, breadcrumbs, bottom panel (Problems/Timeline/Stats), status bar, command palette, settings.json, VS Code keymap, Zen mode | Extras become plain files in Explorer (no custom panel); Timeline view = autosave + commits; minimap replaces the scene strip. Codicons; don't fork Code-OSS (Electron). Editor component: see #27. No VS Code name/logo. |
| 18 | Extras UI | Scratchpad, Todos, Bin each get an **activity-bar icon and open in the left side bar**; **editor tabs are only for story files** (`.fountain`/`.md`) | Supersedes the #17 note that extras open as files/tabs. Files stay in `_river/` on disk; the Explorer hides `_river/`. |
| 19 | Themes | **Two only: Light and Dark** (modelled on VS Code Light/Dark Modern); follow system appearance by default | Version 1 ships these two; **more themes can come later** (user). VS Code theme import deferred, not ruled out. Page preview stays white paper; PDFs always white. |
| 20 | Preview access | A single **preview icon in the editor title bar** (top-right of the tab row) toggles the page preview to the side; ⋯ menu holds Export PDF/FDX and Print | Mirrors VS Code's Markdown "Open Preview to the Side" action |
| 21 | Template selection | **Per-file template dropdown in the editor title bar** next to the preview icon; **default by extension: `.md` → Manuscript, `.fountain` → Screenplay**; "New File" creates `.md` by default; changes stored in `_river/river.json`; no prompt on new project/file | Initially "always Manuscript"; revised so existing screenplays open correctly. Rejected: content detection (can guess wrong), first-open prompt, `Template:` key in the file, choosing at project creation, status-bar picker. |
| 22 | Editor vs page | **Editor is a writing surface:** soft-wrap at a centered column with default margins, unrelated to page lines; **no line numbers**; no page markers/numbers in the editor; page count and runtime live in the preview toolbar; status bar shows words and scenes | Pagination runs only with the preview open or on export. Possible later: optional background page count in the status bar. Script look for screenplays: see #27 |
| 23 | Text layout | **Parley** + River's own pagination; ~~custom Knuth–Plass in v1.1 for justified manuscripts~~ (dropped by #35: monospace, ragged-right) | **Confirmed by the phase-0 typeset spike** (exact positions; 120 pages laid out in 24 ms; `spikes/typeset/NOTES.md`); fallbacks cosmic-text/custom |
| 24 | PDF | **krilla** | Fallback to `pdf-writer` per feature |
| 25 | UI framework | **SolidJS** | React as fallback |
| 26 | Autosave store | **Separate repository in `.git/river-autosave/`** sharing objects via alternates | Replaces private refs in the main repository (leak risk via `--mirror`) |
| 27 | Editor component | **CodeMirror 6** (not Monaco). Screenplay-family files get a **script look** in the editor (cues/parentheticals/dialogue indented and width-limited, transitions right, scene headings bold uppercase) via line decorations from template geometry; Manuscript stays a plain writing surface. Still **no page info** (breaks, headers, footers, page numbers) in the editor | Monaco can't give per-line wrap widths (dialogue column) and is code-oriented for proportional prose; CodeMirror does both natively (Obsidian uses it for Live Preview). Trade-off: more work to match VS Code editor polish (keymap, find widget, minimap). Considered: Monaco light script look, Monaco display-layer projection, pure text |
| 28 | Minimap | **Keep the minimap**, implemented with `@replit/codemirror-minimap` (MIT) | Considered dropping it (Outline/breadcrumbs/@scene already cover navigation); kept for the VS Code look since a ready-made add-on exists |
| 29 | Platforms | ~~**macOS, Windows and Linux at v1**~~ *(superseded by #32)*; philosophy: **multiplatform, slow features** (every feature ships on all three at once, same behaviour, no platform exclusives) | CI matrix on all three; rendering parity via Rust rasterizer + bundled fonts; per-OS integrations behind Rust abstractions. **Superseded by #32** (Linux dropped from v1), then #36 (macOS-only focus; simultaneous-platform philosophy retired) |
| 30 | Updates | **No auto-update, no update checks.** Help → Check for Updates / Subscribe to Updates open the website in the browser; newsletter sign-up on the website only | Keeps the network promise strict (git only). Considered: opt-in automatic checks, app stores. Release flow: tag → tauri-action builds/signs → GitHub Release → newsletter (doc 08) |
| 31 | Shell | **Tauri 2 — locked** | Compared with Electron (more mature, identical engine, easy Linux). Tauri wins for River's focused scope: Rust-native core, no Node runtime, strict network promise by default, lighter. Mac (WKWebView) and Windows (WebView2) are both low-risk |
| 32 | Platforms (revises #29) | ~~**macOS + Windows at v1; Linux later or never**~~ *(superseded by #36)* | Linux's WebKitGTK was Tauri's main risk; not our headache. Community port welcome |
| 33 | Open source | **River will be open source** | License and business model TBD (doc 06) |
| 34 | Future updater | **No auto-update, no Homebrew/winget in v1**, but keep the door open: stable app identity, signing identities, install locations, semver, GitHub Releases assets; updater keypair prepared offline; `createUpdaterArtifacts` off; `update.mode` reserved; network audit as an allow-list | A later updater must be opt-in, signed (Ed25519 + OS signing), never silent; see doc 08 |
| 35 | Font | **One font everywhere: Courier Prime 12 pt** (SIL OFL, bundled), for all templates (Screenplay, Multi-cam, Stage Play, Manuscript) and for the editor. **No font settings**; the user only types | Industry standard: 12 pt Courier (10 cpi, ~1 page/minute); Courier is also accepted for standard manuscript format. Consequences: Manuscript is ragged-right with no justification, hyphenation or small caps (first-line emphasis uses uppercase); Knuth–Plass from #23 dropped; layout is column arithmetic for all templates. Supersedes the prose-serif plan and the editor-font setting (doc 03, doc 05 §7.1/§8.1). Considered: a separate prose serif (Source Serif 4 / EB Garamond / Libre Baskerville) |
| 36 | Platforms and priority (revises #29/#32) | **macOS only for current development and v1. Windows deferred to later; no simultaneous-platform requirement.** Make River the best Mac writing app first | User explicitly retires the multiplatform-first philosophy. Prioritize macOS behaviour, performance and integration; Windows testing, packaging and signing do not gate progress or release. Keep the locked Tauri/Rust stack; do not add portability work at the expense of Mac quality. Linux remains later or never |
| 37 | Workbench UI components | **Kobalte** for accessible controls, wrapped in small River components; **Corvu resizable** for sidebar/editor/preview splits; **CodeMirror 6** for editing; **Tauri native Mac menus/dialogs** where appropriate; shared River CSS tokens | User approved the recommendation and reaffirmed Corvu after reviewing maturity/alternatives (2026-10-18). Implemented in the first Mac workbench (`docs/10-mac-workbench.md`). Centralize styling and component wrappers for maintainability. Do not build menu/focus/keyboard primitives from scratch or adopt a second general UI kit. shadcn-solid considered; direct Kobalte preferred for River’s custom workbench styling |
